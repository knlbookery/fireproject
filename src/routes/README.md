# Current Route Architecture — Migration Context

> **Migration status:** This file documents the route structure inherited from
> the existing TanStack Start implementation. It is provided as migration
> context and must not override the current architecture and refactor
> requirements defined in the repository-root `CLAUDE.md`,
> `INSTRUCTIONS.txt`, and `CODE REFACTOR INSTRUCTIONS.txt`.

The current application uses TanStack Start file-based routing. Each `.tsx`
file in this directory may currently represent a route.

During the approved migration to a static React/TypeScript/Vite SPA, audit
this routing system before changing it. Preserve existing URLs, navigation
behavior, nested layouts, dynamic parameters, and direct-route behavior.

Do not assume that TanStack Start, `__root.tsx`, or the generated route tree
must remain in the final application. Determine whether the current route
structure can be retained through a client-only router or must be migrated
to another approved client-side routing structure.

Do not delete or replace working routes until their replacement has been
implemented and validated.

## Current Pre-Migration Conventions

| File | URL |
| --- | --- |
| `index.tsx` | `/` |
| `about.tsx` | `/about` |
| `users/index.tsx` | `/users` |
| `users/$id.tsx` | `/users/:id` |
| `posts/{-$category}.tsx` | `/posts/:category?` |
| `files/$.tsx` | `/files/*` |
| `_layout.tsx` | Current layout route using `<Outlet />` |
| `__root.tsx` | Current TanStack application shell |

`routeTree.gen.ts` is generated by the current TanStack routing tooling.
Do not edit it manually while that tooling remains active.

## Migration Requirements

The completed route implementation must:

- Operate as part of a static Vite frontend.
- Require no TanStack Start server runtime or SSR process.
- Preserve all approved public URLs.
- Preserve nested layout and parameter behavior where used.
- Support direct visits and browser refreshes through the Apache SPA fallback.
- Keep `/api/` requests outside the frontend route fallback.
- Remove obsolete generated routing files only after their replacement is
  validated.
- Update or remove this file when the final routing architecture is confirmed.
